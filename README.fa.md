# سنجش کیفیت فایل صوتی lossless

[English](README.md)

می‌گوید یک فایل `FLAC` واقعاً بی‌اتلاف است، یا کسی یک `MP3` را باز کرده، دوباره
بسته‌بندی کرده و پسوندش را عوض کرده.

فایل را می‌خواند، طیف فرکانسی‌اش را اندازه می‌گیرد، و از صد به آن نمره می‌دهد.
هم از خط فرمان کار می‌کند هم به صورت یک برنامه کوچک در مرورگر. انگلیسی و فارسی.

## مسئله چیست

یک آلبوم «بی‌اتلاف» می‌خری یا دانلود می‌کنی و بخشی از فایل‌هایش واقعاً بی‌اتلاف
نیستند. کسی یک `MP3` با نرخ ۱۲۸ کیلوبیت را باز کرده، خروجی‌اش را به `FLAC`
تبدیل کرده، و حالا یک فایل سی مگابایتی داری که فقط ۱۲۸ کیلوبیت موسیقی در خود
دارد. ظرف صادق است، محتوا نه. هیچ چیزی در اطلاعات فایل این را لو نمی‌دهد و تا
وقتی بفهمی، نسخه اصلی را پاک کرده‌ای.

ردش در طیف می‌ماند. هر رمزگذار با اتلاف برای صرفه‌جویی، بالای باند را دور
می‌ریزد و این کار را با فیلتری چنان تیز انجام می‌دهد که در طبیعت مشابه ندارد:

| منبع | محتوا تا کجا می‌رود |
|---|---|
| `MP3 128k` | حدود ۱۶ کیلوهرتز |
| `MP3 192-256k` | حدود ۱۸ تا ۱۹ کیلوهرتز |
| `MP3 320k` یا `AAC 256k` | حدود ۲۰ کیلوهرتز |
| سی‌دی واقعی | ۲۲٫۰۵ کیلوهرتز، بدون هیچ پله |

وقتی این را به `FLAC` تبدیل کنی، دیوار دست‌نخورده باقی می‌ماند — چون `FLAC`
بی‌اتلاف است و خرابی را هم با وفاداری کامل ذخیره می‌کند.

## اشتباهی که بیشتر ابزارها می‌کنند

پرسیدن «آیا بالای بیست کیلوهرتز چیزی هست؟» جواب نمی‌دهد. هر فایل شانزده بیتی
نویز دیترینگ دارد و این نویز پهن‌باند است: کف نویزش در یک فایل جعلی هم درست
مثل یک نسخه اصیل تا انتهای باند می‌رسد. با این سؤال همه قبول می‌شوند.

چیزی که آن دو را جدا می‌کند **پله** است. طیف یک ضبط واقعی نرم و تدریجی پایین
می‌آید. یک فایل تبدیل‌شده از پرتگاه می‌افتد — چهل دسی‌بل در عرض ششصد هرتز — و
بعد صاف روی کف نویز ادامه می‌دهد. این ابزار دنبال پرتگاه می‌گردد، نه دنبال
وجود فرکانس بالا.

نسخه اول همین امتیازدهی دقیقاً همین را اشتباه گرفت و تمام فایل‌های جعلی را
سالم اعلام کرد. فایل‌های آزمایشی در پوشه `tests` برای همین هستند که این اتفاق
دوباره بی‌سروصدا نیفتد.

## نصب

پایتون ۳٫۸ یا بالاتر و کتابخانه `libsndfile`. هیچ بسته‌ای از `pip` لازم نیست.

```sh
# Debian / Ubuntu
sudo apt install libsndfile1

# macOS
brew install libsndfile
```

بعد:

```sh
git clone https://github.com/sarabbafrani/lossless-audit
cd lossless-audit
python3 -m losslessaudit.cli path/to/album/
```

یا نصب کامل:

```sh
pip install .
lossless-audit path/to/album/
lossless-audit-gui
```

## خط فرمان

```
$ lossless-audit --lang fa --no-chart suspicious.flac
======================================================================
suspicious.flac
======================================================================
  FLAC / PCM 16 / 44100 Hz / 2 ch / 4:12 / 28.4 MB

  24 / 100   ضعیف — از یک فایل با اتلاف ساخته شده
    پهنای باند              15.4 / 60   دیوار تیز در 15.9 کیلوهرتز
    عمق بیت                 15.0 / 15   16 بیت واقعی
    نرخ نمونه‌برداری        10.0 / 10   44100 هرتز
    سقف و بریدگی            15.0 / 15   بدون بریدگی
```

بدون `--no-chart` نمودار طیف را هم می‌کشد، که معمولاً برای دیدن دیوار با چشم
خودت کافی است.

گزینه‌های مفید:

```
--lang en|fa       زبان خروجی (پیش‌فرض از تنظیمات سیستم)
--json             خروجی ماشین‌خوان برای اسکریپت‌نویسی
--fail-under N     اگر چیزی زیر N بگیرد با کد خطا خارج شو
--no-chart         فقط عددها
```

با `--fail-under` می‌شود به عنوان دروازه کنترل کیفیت استفاده‌اش کرد:

```sh
lossless-audit --fail-under 80 --no-chart ~/Music/ || echo "something is fake"
```

## رابط گرافیکی

```sh
lossless-audit-gui
```

یک صفحه روی `127.0.0.1` باز می‌کند. فایل‌ها را رویش بکش و بینداز، یا مسیر یک
پوشه را بده. هر فایل یک حلقه نمره می‌گیرد، طیفش با علامت روی دیوار، و ریز
امتیازها. یک دکمه بین فارسی و انگلیسی جابه‌جا می‌کند، بدون اینکه چیزی دوباره
خوانده شود.

سرور فقط روی `localhost` گوش می‌دهد و هیچ چیزی جایی آپلود نمی‌شود — فایل‌ها را
همان پردازه‌ای می‌خواند که صفحه را می‌سازد.

## نمره چطور ساخته می‌شود

صد امتیاز روی چهار چیزی که یک فایل می‌تواند اشتباه داشته باشد:

| بخش | امتیاز | چه چیزی را می‌گیرد |
|---|---:|---|
| پهنای باند | ۶۰ | دیوار رمزگذار با اتلاف |
| عمق بیت | ۱۵ | فایل بیست و چهار بیتی که از شانزده بیت پر شده |
| نرخ نمونه‌برداری | ۱۰ | فایل ۹۶ کیلوهرتزی که از سی‌دی بالا برده شده |
| سقف و بریدگی | ۱۵ | بریدگی و مسترهای فشرده |

وقتی دیوار قطعی شود، سقف نمره کل می‌آید پایین — نه اینکه فقط سیزده امتیاز کم
شود. دلیلش این است که یک فایل جعلی در سه معیار دیگر آزاد است نمره کامل بگیرد:
نسخه اولیه به یک فایل جعلی شناخته‌شده ۸۷ از ۱۰۰ داد. با این سقف، دیوار در بیست
کیلوهرتز حدود ۵۱ می‌گیرد و دیوار در شانزده کیلوهرتز حدود ۲۴.

منحنی‌های دقیق در `docs/scoring.md` هست.

## چه چیزهایی را نمی‌تواند بگوید

این را باید صریح گفت، چون یک عدد از صد بیشتر از آنچه حقش است اعتماد می‌گیرد.

**فایل را می‌سنجد، نه موسیقی را.** یک نسخه واقعاً بی‌اتلاف از ضبطی مونو در سال
۱۹۵۵ بالای پانزده کیلوهرتز چیزی ندارد، چون میکروفون آن زمان ضبط نکرده. دیواری
در کار نیست پس نمره خوبی می‌گیرد — و درست هم هست، چون فایل سالم است — ولی نمره
هیچ نمی‌گوید که خوب به گوش می‌رسد یا نه.

**نویز بالای دیوار گولش می‌زند.** اگر کسی بعد از تبدیل، نویز مصنوعی روی
فرکانس‌های بالا بریزد، پرتگاه پر می‌شود و فایل قبول می‌شود. این نادر است و
تقلب عمدی محسوب می‌شود نه تنبلی، ولی شدنی است.

**طبیعی بودن را نمی‌سنجد.** فایلی که طیفش از سیزده تا چهل و شش کیلوهرتز کاملاً
صاف است موسیقی نیست، ولی اینجا چیزی به آن اعتراض نمی‌کند. تشخیص این مورد قدم
بعدی واضحی است و هنوز پیاده نشده.

**فقط زیر ۲۰٫۷ کیلوهرتز.** دیواری نزدیک‌تر از این به نایکوئیست گزارش می‌شود
ولی به عنوان اثبات در نظر گرفته نمی‌شود، چون تغییردهنده‌های نرخ نمونه‌برداری هم
نشانه مشابه می‌گذارند.

نمره پایین را شاهد قوی بگیر و نمره بالا را نبودِ همان شاهدی که این ابزار دنبالش
است. ولی وقتی چهل دسی‌بل افت در شانزده کیلوهرتز نشانت داد، جای شک زیادی نمی‌ماند.

## تست‌ها

```sh
cd tests && python3 -m unittest test_engine -v
```

فایل‌های آزمایشی در حوزه فرکانس ساخته می‌شوند با نقطه قطعی که خود تست انتخاب
کرده، پس جواب درست از قبل معلوم است و هیچ فایل صوتی در مخزن نگهداری نمی‌شود.
نویز دیترینگ هم دارند، دقیقاً برای اینکه ابزار نتواند از راه میان‌بری که بالاتر
توضیح داده شد قبول شود.
